UVA Knowledge Network

A private, locally hosted pipeline that turns coursework (PDFs, slides, spreadsheets, class recordings) into structured, searchable notes, using local models so course material never leaves my machine.

PythonLocal vision-language modelsOCRBM25 searchEvaluation sets
Read the brief

The problem

Ten courses of material sat in scattered formats, so finding how one idea connected across classes meant re-reading everything.

What I built

  • Converters for PDFs, slide decks, spreadsheets and video transcripts into markdown with metadata (700+ documents across 10 courses).
  • An image workflow where a local vision-language model classifies each page as a graph, diagram, table or text and describes the figures.
  • Automated experiment loops that benchmark model, prompt and image-size variants against a hand-checked set and adopt a change only when it wins.
  • A keyword search prototype over 7,000+ text chunks, the foundation for question answering across courses.

How I tested it

I labelled a 19-page set by hand and scored every variant against it. Page-type accuracy rose from 71% to 100% once the prompt asked for the page type on its own line. The table shows the leaderboard from one report.

Bars are drawn from 0.80 to 1.00 so the differences are visible. Prompt v5 looked reasonable but lowered the score because it broke slides that mix figures and text, so I did not adopt it.

What I learned

Several apparent model failures were really bugs in my own scoring code. I now read the raw outputs before I trust a metric.

The code and data are private because they contain coursework. Next up: retrieval agents that answer questions across courses.

Job-Application Tracker

A local dashboard that tracks every application through defined statuses with deadlines, a follow-up queue and drafted follow-up emails. The demo runs entirely in your browser on made-up sample data.

Python standard libraryJavaScriptUnit testsVersion-controlled data
Open the live demo
Read the brief

The problem

I was managing more than 50 applications, each with its own deadline, requirements and follow-up date. Notes in scattered documents were not going to hold.

What I built

  • A Python API and a single-page front end that saves every change to a JSON file I can review in git.
  • Forms that reject invalid dates, scores and statuses.
  • Views for what needs attention now: submissions to confirm, follow-ups due and upcoming deadlines.
  • Controls against cross-site and DNS-rebinding requests: loopback-only binding, Host checks and JSON-only writes.

How I tested it

Automated unit tests cover validation, saving and the request checks. I built it with AI coding assistants and reviewed their work through the tests, which caught a date-validation bug that would have dropped connections.

The real tracker holds personal application data, so its repository is private. This demo uses invented companies.

The problem

Announcements were missed and there was no single, reliable record of members, because everything lived in Flare, Snapchat and GroupMe.

What I did

I gathered requirements from members, built the platform and released it in small steps. Members raised concerns about cost, time to adopt and design, and I addressed them by prioritizing their feedback.

The result

Other brothers now contribute to the project, it supports alumni connections, and the membership database is being extended to help manage house access.

The platform holds member data, so it is private and there are no screenshots here.
